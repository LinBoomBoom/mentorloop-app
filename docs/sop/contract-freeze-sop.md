生成日期：2026-09-24
归属：SOP 系统 L3 执行层 · 生命周期阶段 ① 定义出口
上游：`task-card-sop.md`；下游：`quality-gate-sop.md`（G2）

---

## 1. 目的与适用

客户端与后端**先冻结接口契约再并行**（文档 05 协同铁律）。任何触碰契约的改动，必须先冻结、双签，再开工。

**触发条件（命中任一即需冻结）**：

- 改 `types/*.uts`（`interview` / `scoring` / `resume` / `auth` / `tracking`）
- 改 `api/*.uts`（`client` / `env` / `auth` / `interview` / `resume` / `report` / `membership` / `asr` / `tracking` / `speech`）
- 改服务端出参结构：`server/src/types/*.ts`、`server/src/routes/*.ts`、`server/src/rules/*`（与前端 `engine/` 镜像）
- 新增 / 删除 / 重命名端点

**不触发**：纯内部重构（字段与语义不变）、纯 UI 调整、纯文档。

---

## 2. 冻结对象与单一事实来源

| 契约面     | 权威文件                          | 说明                              |
| ---------- | --------------------------------- | --------------------------------- |
| 客户端类型 | `types/*.uts`                     | UTS `type` 定义，字段即契约       |
| 客户端调用 | `api/*.uts`                       | 文件头注释即端点契约              |
| 服务端类型 | `server/src/types/*.ts`           | 必须与 `types/*.uts` 字段一一对应 |
| 服务端出参 | `server/src/routes/*.ts`          | 统一响应 `{code, data, message}`  |
| 规则镜像   | `server/src/rules/*` ↔ `engine/*` | 选题/评分逻辑两端一致             |

---

## 3. 流程

1. **识别**：从任务卡「依赖」段确认是否触碰契约。
2. **起草**：填写契约冻结单（见 §4），列明端点、字段 diff、影响面。
3. **双签**：客户端与后端各签一次；任一未签 → 不得开工。
4. **记录**：冻结单写入 `docs/contracts/YYYY-MM-DD-<slug>.freeze.md`。
5. **实现**：两端按冻结单并行实现。
6. **校验**：G2 门禁中核对两端字段一致（见 `quality-gate-sop.md` §4）。

## 5. 冻结后纪律

- 冻结后**再变更**须重新走本流程（重签），并在任务卡「风险」登记变更原因。
- 变更若影响评分/选题规则 → 必须重跑固定评测集（见 `domain-content-sop.md`）。
- 变更若影响服务端逻辑 → 同步 `server/src/rules/*` 镜像，保持两端一致。

---

## 6. 失败动作

- 未双签即开工 → 停止，退回「① 定义」。
- 两端字段不一致被 G2 拦下 → 回到本 SOP 重新冻结。
