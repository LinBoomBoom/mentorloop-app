# 链式流水线 SOP（Pipeline）

生成日期：2026-09-24
归属：SOP 系统 L3 执行层 · 流转机制
上游：[README.md](./README.md)；相关：[roles-sop.md](./roles-sop.md)（角色）、各门禁 SOP

---

## 1. 目的与适用

把生命周期从「多角色共商」改为「**顺序流转 + 产物交接 + 门禁裁决**」。不要求多角色同时在场，任务按链逐环推进：**一环一产物，产物不齐不流转。**

**适用**：所有常规任务推进。
**不适用**：架构级决策、范围争议（见 §8，改用共商）。

---

## 2. 链型（按风险裁剪）

| 链型       | 适用            | 环节                                        | SOP 增量（粗估） |
| ---------- | --------------- | ------------------------------------------- | ---------------- |
| **微链**   | 单点修复、文档  | 实现 → G2                                   | ~1–2k            |
| **标准链** | 常规功能        | 任务卡(G1) → 实现 → G2 → G3                 | ~5–7k            |
| **完整链** | 契约变更 / 发布 | 任务卡(G1) → 契约冻结 → 实现 → G2 → G3 → G4 | ~8–12k           |

> 链长裁剪是**主要节流阀**。禁止对小改动过度拉链。

---

## 3. 角色挂链位（不共商，按位登场）

| 链位     | 角色         | 触发条件                  | 产物                     |
| -------- | ------------ | ------------------------- | ------------------------ |
| 建卡     | PO           | 标准链起                  | 任务卡（八要素，含角色） |
| 可行性   | FA           | 涉及框架能力 / 版本 / POC | 可行性结论               |
| 平台约束 | MP-PM        | 涉及小程序端              | 小程序需求规格           |
| 实现     | FE / BE / AI | 总是                      | 代码 + 单测              |
| 质量门   | QA           | 标准链起                  | 门禁记录（G2）           |
| 设计走查 | UX           | 涉及 UI 改动              | 设计评审结论             |
| 准入     | QA           | 标准链起                  | 验收结论（G3）           |
| 发布     | QA + LC      | 仅发布                    | 发布准入单（G4）         |

---

## 4. 每环产物契约（链的燃料）

子代理**无状态**，上下文只靠产物传递。产物必须落盘，不得只留在对话里。

| 环   | 产物路径                                     | 下一环如何消费           |
| ---- | -------------------------------------------- | ------------------------ |
| 建卡 | `docs/tasks/YYYY-MM-DD-<slug>.md`            | 读「范围 / 验收 / 角色」 |
| 冻结 | `docs/contracts/YYYY-MM-DD-<slug>.freeze.md` | 读「字段 diff / 双签」   |
| 门禁 | `docs/tasks/YYYY-MM-DD-<slug>.gate.md`       | 读「结论 / 失败项」      |
| 准入 | `docs/tasks/YYYY-MM-DD-<slug>.accept.md`     | 读「验收核验 / 红线」    |
| 发布 | `docs/releases/YYYY-MM-DD-<version>.md`      | 读「前置条件核验」       |

---

## 5. 默认瘦模式（成本控制）

| 层         | 默认                           | 升级条件                                                      |
| ---------- | ------------------------------ | ------------------------------------------------------------- |
| 链式流转   | ✅ 始终（顺序 + 产物 + 门禁）  | —                                                             |
| 加载 skill | ✅ 只加载**命中链位的 1–2 个** | —                                                             |
| 起子代理   | ❌ **默认不起**                | 仅 G2 / G3 需**独立视角**，或任务跨模块复杂时，**只对该环**起 |

> 链式的主要价值是**流程约束**，不是算力开销。子代理是「用总账单换主上下文干净」，非必要不起。

---

## 6. 节流规则（强制 7 条）

1. **只加载命中链位的 skill**，绝不把全部 skill 都加载。
2. **SOP 文档按需读章节**，不整篇读；`README.md` 尽量少读。
3. **产物落盘**，不在对话里重复粘贴内容。
4. **门禁输出收窄**：只取退出码 / 失败行，不灌全量测试输出。
5. **链长裁剪**：微链几乎零 SOP 开销。
6. **同环检查合并**为一条命令。
7. **子代理单环化**：只对需要独立视角的那一环起，提示词直接给产物路径。

---

## 7. 断链处理

| 情况                             | 处理                                 |
| -------------------------------- | ------------------------------------ |
| 产物缺失                         | **不得流转**，回到该环重做           |
| G2 门禁失败                      | 回退到「实现」环，修复后从第一项重跑 |
| G3 准入失败                      | 打回「② 构建」                       |
| 链型判断偏重（小改动误判完整链） | 允许**降级**链型，并说明理由         |
| 触及契约但未冻结                 | 停下，插入「契约冻结」环             |

---

## 8. 何时改用共商

仅两类场景保留多角色共商：**架构级决策**、**范围争议**——这两类必须 PO / FA / UX 同时在场，链式走不通。其余一律走链。
