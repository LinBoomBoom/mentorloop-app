# 验收准入 SOP（G3 准入门）

生成日期：2026-09-24
归属：SOP 系统 L3 执行层 · 生命周期阶段 ③ 验证出口
上游：`quality-gate-sop.md`（G2）；下游：`release-sop.md`（G4）

---

## 1. 目的与适用

G2 保证「代码是干净的」，G3 保证「**做对了**」。构建产物在进入「④ 交付」前，必须经代码审查、安全审查与验收核验，并给出**书面准入结论**。

**适用**：所有进入验证阶段的代码改动。
**不适用**：纯文档改动（可跳过，但需在 commit 说明）。

---

## 2. 检查项

| #   | 检查项       | 手段                      | 通过标准                             | 阻断 |
| --- | ------------ | ------------------------- | ------------------------------------ | ---- |
| 1   | 代码审查     | `TRAE-code-review`        | 无阻断级问题（正确性/回归/可维护性） | 是   |
| 2   | 安全审查     | `TRAE-security-review`    | 无高危、无本次变更引入的可利用风险   | 是   |
| 3   | 验收核验     | 对照任务卡 §4「验收标准」 | 逐项通过，**不得**主观放行           | 是   |
| 4   | 产品红线复核 | 人工/审查                 | 见 §3                                | 是   |
| 5   | 契约一致性   | 对照契约冻结单            | 两端字段一一对应                     | 是   |

---

## 3. 产品红线复核清单（文档 02/03）

- [ ] 面试房间**不显示实时评分**。
- [ ] 追问深挖 **≤2 层**；无羞辱性、循环、隐私追问。
- [ ] 评分**必须引用证据**；低置信度**不伪装**精确分数。
- [ ] LLM 只做解释与示例，**未篡改**原始证据与分数。
- [ ] AI 改写标「建议稿」；疑似虚构数据醒目标记。
- [ ] AI **不伪装**真人（明确「AI 面试官」标识）。
- [ ] 无障碍：不只靠颜色表状态；字幕/文字模式可用。

---

## 4. 流程

1. 提交审查：对本次变更跑 `TRAE-code-review` 与 `TRAE-security-review`。
2. 记录结论：阻断项必须修复；修复后重跑（含 G2）。
3. 验收核验：逐项对照任务卡验收标准勾选。
4. 红线复核：按 §3 清单确认。
5. 出结论：填写验收结论，明确「通过 / 不通过」与签字人。

---

## 6. 失败动作

- 存在阻断项 → **打回「② 构建」**，修复后从 G2 重跑。
- 验收标准任一项不通过 → 不得进入交付；若确需降级验收，须在任务卡「风险」登记并由产品负责人确认。
- 不得以「时间紧」为由跳过安全审查或红线复核。
