# HBuilderX 5.26 运行模式产物 app.wxss 聚合页面样式导致 WXSS 编译错误

## 问题现象

HBuilderX「运行到微信开发者工具」后，开发者工具报 `[WXSS 文件编译错误] path '../../uvue.wxss' not found from './app.wxss'`，全部页面样式失效、无法正常展示。同一时间 CLI `pnpm build:mp-weixin` 产物完全正常。

## 问题分析

- 项目为样式隔离策略 2.0（uni-app x 编译器 5.26）。该策略下 uni-mp-vite 给每个页面 wxss 头部注入 `@import "../../uvue.wxss"`（`configResolved.js` 按**页面所在目录**计算相对路径），并给 App.uvue 注入 `@import "/uvue.wxss"`（根路径，`polyfill.js` 硬编码）。
- CLI build：样式按页面拆分，pages/xxx/*.wxss 内的 `../../uvue.wxss` 解析正确。
- HBuilderX 运行模式：把全部页面/组件样式**聚合进根目录 app.wxss**（172KB，含 34 处 `../../uvue.wxss`），相对路径基准未随聚合调整，`../../` 越出小程序根目录 → 工具编译失败。

诊断特征：报错路径带 `../../` 但 app.wxss 自身只应有 `/uvue.wxss`；`unpackage/dist/dev/mp-weixin` 出现巨型 app.wxss 即中招。

## 处理措施

- 弃用 HBuilderX 运行产物 `unpackage/dist/dev/mp-weixin`，微信开发者工具改导入 CLI watch 产物 `dist/dev/mp-weixin`（`pnpm dev:mp-weixin` 常驻，实测 app.wxss 580B、0 处污染 import）。
- HBuilderX 停止运行会话，避免继续产出坏产物。
- 本机曾出现 CLI watch 与 HBuilderX 运行**双 watch 并行**分别写 `dist/dev` 与 `unpackage/dist/dev`，易误判产物来源；排查时先确认开发者工具实际导入的目录。

## 后续建议

- MP 端开发循环固定为：`pnpm dev:mp-weixin`（CLI watch 常驻）+ 开发者工具导入 `dist/dev/mp-weixin`；HBuilderX 仅用于 App 端真机调试。
- 若 HBuilderX 后续版本修复聚合路径，可回归验证后再启用其运行模式。
- 涉及平台编译行为的差异，优先对比「CLI 产物 vs HBuilderX 产物」同文件内容定位。
