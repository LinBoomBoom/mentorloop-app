# 面试房间 / 专项训练房间小屏纵向挤压

## 问题现象

小屏设备（iPhone SE 375×667，以及更矮机型）上，进入面试房间或专项训练房间并完成一次语音作答后，出现「识别结果 · 请确认」卡，页面纵向空间不足：

- 题目卡与识别确认卡相互挤占，底部控制条上移或内容溢出可视区。
- 专项训练房间外层为 `overflow-hidden`，溢出部分被直接裁切（进度点 / 确认按钮可能不可见）。
- 面试房间确认态虽已隐藏 128px 语音可视化，题目卡内的「再说一遍 / 换一种说法 / 文字作答」辅助行仍保留，挤压依旧存在。

## 问题分析

两个房间均为「固定满屏 + 无滚动」的沉浸式布局，新增确认卡后缺少可伸缩空间：

- [pages/interview/room.uvue](../../../../pages/interview/room.uvue#L2-L215)：外层 `flex-col h-screen`，主区 `flex-1`，语音可视化固定 `height: 128px`，控制条固定底部；确认卡追加在题目卡下方（`textarea h-24` + 双按钮）。375×667 上主区可用高度约 330px，题目卡 + 确认卡实际约 450px。
- [pages/training/room.uvue](../../../../pages/training/room.uvue#L2-L154)：外层 `flex-col h-screen overflow-hidden`，主区 `flex-1`，题目卡 + 确认卡 + 进度点全部写在固定高度内，无 `scroll-view` 兜底。

结论：不是单个组件的样式缺陷，而是页面排版结构未为「确认态」预留纵向空间。

## 处理措施

- 暂不修改代码。已确认的计划是重新设计这两个页面的排版布局，届时一并解决，避免现在做局部压缩改动后被推翻。
- 当前线上仅保留「确认态隐藏语音可视化」这一处缓解措施。

## 后续建议

- 重新设计时，主内容区应可滚动（`scroll-view`）或按状态重新分配层级，底部控制条固定；不要继续用「隐藏元素」换取空间。
- 修订后需在 375×667 真机/模拟器截图验收：题目卡、确认卡、双按钮、控制条均完整可见且无裁切。
- 其余页面（首页、报告、简历等）已有 `scroll-view`，不属于本问题；登录页虽无滚动但仅 App 端使用，不在小程序主链路。
