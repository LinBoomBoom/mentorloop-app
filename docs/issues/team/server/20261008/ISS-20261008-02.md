# ASI 陷阱：语句结尾无分号 + 下一行以 `(await` 开头被解析为函数调用

## 问题现象

`stats.get.ts` 云端注册→统计路径恒 500，本地 vitest 全绿（stats 的已登录分支无覆盖）。

## 问题分析

代码形如：

```js
const x = {}
(await someAsync())...
```

由于上一行无分号，ASI 规则将下一行的 `(` 视为对 `{}` 的函数调用，抛出 `{} is not a function`。本地测试未命中该分支，故未暴露。

## 处理措施

在 `stats.get.ts` 修复分号。新增 `tests/asi-guard.test.mjs` 扫描 `server/` 源码，检测「以 `}` 或 `)` 结尾的行 + 下一行以 `(await` 开头」模式，命中即失败。

## 后续建议

- 服务端代码统一末尾加分号（项目已有 prettier 配置）。
- ASI 守卫测试已纳入 CI，新增同类模式会被拦截。
