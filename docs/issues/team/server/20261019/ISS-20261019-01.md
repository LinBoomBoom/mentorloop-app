# 题面生成把「本身已是完整问句」的云题 q 再套一层模板，产出病句

## 问题现象

批次 A G3 真机走查（backend 方向实开一场）时，面试房间 Q1 显示：

> 请说明「错误消息会跨进程透传给调用方，为什么必须脱敏？请举例说明哪些内容绝对不能放进 error message，并给出正确的写法。」的原理，并结合你的项目经历谈谈实际处理方式。

即：题面 = 模板（`请说明「{q}」的原理，并结合你的项目经历谈谈实际处理方式。`）包住了云题原始 `q`，而这条 `q` 本身就已经是一句完整问句（含「为什么…？」「请举例…」），叠加后语义重复、可读性差。

## 问题分析

- 适配层 `server/src/rules/question-phrasing.ts` 的假设是「云题 `q` 是知识点标题（如『DNS 解析过程』）」——该假设来自抽样取证（多数 `q` 确实如此），但**并非全部**：存在 `q` 本身就是完整设问的条目。
- 模板对两类输入不区分：知识点型标题需要包装，问句型标题不应再包装（最多加轻量前缀，如「请回答：」或直接原样使用）。
- 影响面：凡 `q` 含「？」或「为什么/请举例/如何/哪些」等设问特征的题，题面都会变成病句；`content` 列是**同步时预计算**的，因此修一次需重跑同步（本表非空时被 `ifEmpty` 跳过 → 需先清表再重同步）。

## 处理措施（待定，见「是否需决策」）

建议方案（择一，需 PO/内容裁决）：

1. `phraseQuestion` 增加「问句型判定」：命中设问特征（`?`/`？`/为什么/如何/哪些/请举例/请说明）时不再套模板，直接使用原 `q`（必要时加前缀「请回答：」）；
2. 或在同步时把这类 `q` 标记出来，交由内容侧（content-review）改写为知识点标题后再入库。

配套动作：修完后必须重跑内容库同步（TRUNCATE `mentorloop_mp.questions` → 重启容器触发 ifEmpty 自举，或本地 CLI 同步），并加单测锁死「问句型不二次包装」。

## 后续建议

- 批次 A 设计稿 §5.5 的模板假设应补一条前提：**模板只适用于知识点标题型 `q`，问句型 `q` 需直通**。
- 抽样取证要覆盖「q 形态」多样性，不能只按多数样本定规则（本次即多数样本误导）。
- 内容质量类问题在真机走查中最容易暴露——本卡 G3 走查一轮即发现。
