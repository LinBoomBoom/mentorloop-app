# 换机后新 clone 工作区行尾为陈旧 CRLF，`pnpm format:check` 全仓误报 65 文件

## 问题现象

换机后首次在新机器 clone 仓库并跑 G2 门禁：`pnpm format:check` 对 65 个文件报格式告警（`.md`/`.uvue`/`.uts`/`.mjs`/`.css` 等），`pnpm lint` 正常。告警文件与 2026-10-16 提交 `0cfb253`（`.gitattributes` 统一 LF）声称「format:check 全绿」矛盾。

## 问题分析

- `git ls-files --eol` 实测：索引层全部 `i/lf`（仓库 blob 干净），工作区 72 个文件 `w/crlf`，属性 `attr/text=auto eol=lf` 已生效——即**工作区是陈旧 smudge 产物**：新机器 clone/checkout 时 `core.autocrlf=true` 先行生成了 CRLF，`.gitattributes` 的 `eol=lf` 只约束后续 smudge，不会自动重写已落盘文件。
- prettier 以磁盘原始字节做检查（`endOfLine: 'lf'`），CRLF 工作区 → 65 个被 prettier 覆盖的文件全部误报；其余 7 个 CRLF 文件不在 prettier 检查范围。
- **`git checkout -- <path>` 无法修复**：文件 clean 后与索引一致（差异纯为行尾），git 判定 up-to-date 直接跳过重写。

## 处理措施

对 72 个 `w/crlf` 且**无本地修改**的文件执行「删除 → 重新检出」，强制走一遍当前属性下的 smudge：

```powershell
$list = git -c core.quotepath=false ls-files --eol | Where-Object { $_ -match 'w/crlf' } | ForEach-Object { ($_ -split "`t")[-1] }
$targets = @($list | Where-Object { $mod -notcontains $_ })   # $mod = git status --porcelain 里的已改文件
$targets | ForEach-Object { Remove-Item -LiteralPath $_ }
git -c core.quotepath=false checkout -- @targets
```

结果：残余 CRLF 0，`git status` 中 72 个行尾幽灵改动全部消失（索引本就是 LF，无内容变化），`pnpm format:check` 全绿。注意中文文件名需 `-c core.quotepath=false`，否则 octal 转义路径导致 pathspec 不匹配。

## 后续建议

- 换机/新 clone 后先跑 `git ls-files --eol | Select-String "w/crlf"` 检查工作区行尾，再跑门禁；有残余按上述「删除 + 重检出」处理（只处理无本地修改的文件）。
- G2 遇到全仓 format 误报时，先用 `git ls-files --eol` 区分「行尾幽灵」与「真实格式问题」，避免误改内容。
