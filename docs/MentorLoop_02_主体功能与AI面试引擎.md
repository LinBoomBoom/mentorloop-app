# MentorLoop AI 面试产品：主体功能与 AI 面试引擎

## 1. 信息架构

```text
首页
├─ 开始面试
├─ 快速专项训练
├─ 简历优化
├─ 我的成长
└─ 我的

开始面试
├─ 目标岗位与难度
├─ 简历/经历确认
├─ 设备检测
├─ 数字人面试房间
├─ 面试总结
└─ 详细报告
```

## 2. 主体功能

### 2.1 入职画像与岗位蓝图

- 上传 PDF/Word/图片简历，提示用户确认解析结果。
- 选择目标岗位、经验区间、公司类型、面试语言和面试目标。
- 生成“岗位能力蓝图”：基础知识、工程能力、项目深度、系统设计、沟通表达、职业动机六类能力。
- 给出用户经历与岗位要求的匹配项、缺失项和高风险追问点。

### 2.2 AI 数字人面试

- 可选快练（5 分钟）、标准面（20 分钟）、深度面（40 分钟）。
- 面试开始前进行麦克风、网络、环境和授权检测。
- 数字人以语音、字幕、表情和节奏引导面试。
- 用户可语音作答；可开启文字辅助输入，但正式评分需要标记输入方式。
- 支持暂停、异常恢复、跳过和重新作答；跳过会成为报告证据而非静默丢弃。

### 2.3 题库与专项训练

- 按岗位、能力、知识点、难度、常见误区、题型和答案证据要求组织题目。
- 提供 3/5/10 分钟碎片化训练。
- 将报告中的薄弱项一键加入训练计划。
- 为用户记录错因：不会、说不清、项目证据不足、推理不完整、表达结构差。

### 2.4 AI 简历优化

- 简历完整性检测：联系方式、项目、技术栈、量化成果、空档期、格式风险。
- 与目标岗位做关键词和能力项匹配，不使用简单堆词评分。
- 逐段改写建议：保留事实、突出行动、量化结果、标注需要用户补充的证据。
- 支持生成不同投递版本及导出。

### 2.5 报告与成长档案

- 总评、能力雷达、题目表现、关键证据、风险问题、优秀回答示例。
- 7/14 天训练计划，按优先级安排任务。
- 展示多次模拟的能力变化；避免只比较总分，应比较具体能力和证据覆盖率。

## 3. 自主设计的 AI 面试引擎

面试能力不依赖现有 Web 端方案，按以下五层独立设计。

### 3.1 岗位能力图谱

每个岗位由能力域、子能力、可观测行为、题目簇、评分锚点组成。例如 Java 后端岗位：

```text
并发与 JVM → 问题定位 → 能否说明指标、假设、验证和结果
系统设计 → 容量与权衡 → 能否说明约束、备选方案与取舍
项目经历 → 个人贡献 → 能否区分团队成果与个人决策
表达能力 → STAR/结构化叙述 → 是否先结论、再证据、后反思
```

### 3.2 题目选择器

输入为岗位蓝图、简历风险、已答题目、剩余时间和实时可信度。输出为下一道题及提问目的。

选择规则：

1. 先覆盖岗位最低门槛能力。
2. 对简历中的高价值项目做验证性追问。
3. 对回答模糊、绝对化、缺少指标或前后矛盾的内容深挖。
4. 保留至少一道开放题评估学习能力与复盘能力。
5. 依据时间预算动态收束，避免无止境追问。

### 3.3 追问策略

追问按意图分类，而非由模型自由发挥：

- 澄清：术语、角色、范围、约束不清。
- 证据：要求具体指标、日志、代码、决策或个人贡献。
- 深挖：从“做了什么”进入“为什么这样做、替代方案是什么”。
- 反例：询问失败场景、边界条件和故障恢复。
- 迁移：把原项目方法迁移到新问题。
- 收束：总结用户回答，转向下一个能力域。

单个知识点最多深挖两层；无效循环、羞辱性追问和与岗位无关的隐私问题必须禁止。

### 3.4 评分引擎

评分采用“量表 + 证据 + 校准”，而不是让大模型直接给总分。

| 维度             | 权重建议 | 评分证据                   |
| ---------------- | -------: | -------------------------- |
| 岗位知识与正确性 |      25% | 概念、原理、边界条件       |
| 项目与工程实践   |      25% | 个人贡献、指标、工具与结果 |
| 问题分析与权衡   |      20% | 假设、方案比较、风险控制   |
| 表达与沟通       |      15% | 结构、清晰度、回应追问能力 |
| 学习与复盘       |      10% | 失败经验、纠偏、成长路径   |
| 职业动机与匹配   |       5% | 目标一致性与诚实边界       |

每个维度给出等级、置信度、引用证据、缺失证据和建议训练题。低置信度不应伪装为精确分数。

### 3.5 报告生成器

报告先使用结构化评分数据生成，再由语言模型负责解释与练习建议。模型不得改变已经确认的原始证据和分数来源。

## 4. 自研数字人方案

### 4.1 角色形态

MVP 采用“专业、克制、可信”的 2.5D 半身面试官，而非夸张拟真人或高成本 3D 虚拟主播。角色可分为：技术面试官、HR 面试官、严格挑战型、友好教练型。

### 4.2 驱动系统

```text
TTS 音频与文本
→ 音素/时间轴
→ 口型 Blend Shape 或序列帧
→ 表情状态机
→ 姿态与手势动作
→ 2.5D 渲染层
```

- 空闲：呼吸、微眼动、偶发点头。
- 提问：稳定目光、清晰嘴型、轻量手势。
- 倾听：低频点头、避免频繁动画干扰用户。
- 追问：表情更专注，改变节奏但不制造压力羞辱。
- 总结：正向但不虚假的反馈。

### 4.3 语音多品质策略

- 标准档：低延迟、成本可控，用于默认模拟。
- 精品档：更自然的发音、停顿与多语言支持，用于会员体验。
- 情绪档：更丰富的韵律与角色人格，用于沉浸式正式面试。

不把声音克隆作为默认功能。若未来提供，应仅支持经明确书面授权的本人声音，并提供删除、撤回和滥用申诉机制。
