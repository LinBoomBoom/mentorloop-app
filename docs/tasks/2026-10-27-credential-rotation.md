- 来源：系统问题清单 P3-9 / 简历验收 §5 待办 8；2026-10-26 与 2026-10-27 两次 `tcb cloudrun detail` 回读把 EnvParams 明文打印进了终端

## 1. 目标

把已进入过工具日志的全部生产密钥视为「已泄露」，逐项替换为新值并回读确认，使旧值失效；同时清理云端残留的弱验证码开关。轮换完成后，线上不得存在任何曾出现在日志中的密钥。

| 1   | `MYSQL_PASSWORD`                        | 直连生产库读写全部用户数据                   | 腾讯云 TDSQL-C → 实例 → 账号管理   | 否         |

## 3. 执行策略（关键：把 6 次部署压成 1 次）

云托管的环境变量**只在新版本生效**（本次已验证：改配置不会热更新）。逐项轮换意味着 6 次注入 + 6 次部署（约 25 分钟纯等待）。因此：

1. 你按 §4 在各控制台生成新值，写入本地文件（不贴聊天）；
2. 我一次性读取、合并全量 EnvParams，**一次回写 + 一次部署**；
3. 部署后逐项验证（§6），失败即按 §7 回滚。

> ⚠️ **已踩到的陷阱（2026-10-27）**：`UpdateCloudRunServerConfig` 对 `ServerBaseConfig` 是**覆盖**语义。此前注入/移除临时令牌时只传了 `EnvId / ServerName / EnvParams`，导致容器规格被重置为默认 **1C/2G**（原为降配后的 0.5C/1G）。因此本次回写必须显式带上 `Cpu / Mem / MinNum / MaxNum / Port / OpenAccessTypes`，并在回读时逐项核对。

## 4. 需要你做的（按顺序，互不阻塞）

把新值写到 `D:\mentorloop-secrets\rotation-2026-10-27.txt`，格式一行一个 `KEY=value`：

```
MYSQL_PASSWORD=<新密码>
WX_SECRET=<新 AppSecret>
TENCENTCLOUD_SECRET_ID=<新 SecretId>
TENCENTCLOUD_SECRET_KEY=<新 SecretKey>
LLM_API_KEY=<新 DeepSeek Key>
MP_APP_KEY=<新虚拟支付 AppKey>
```

各项注意：

| 项                      | 操作要点                                                                                                                     |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `MYSQL_PASSWORD`        | 先在 TDSQL-C 改账号密码，**不要**先改 EnvParams，否则服务立刻连不上；改完库密码后 5 分钟内完成注入即可（期间容器会重连失败） |
| `WX_SECRET`             | 微信公众平台「重置」后旧值立即失效，线上微信登录/存储/支付会中断，需与部署窗口贴紧                                           |
| `TENCENTCLOUD_SECRET_*` | 建议**新建**子用户密钥再禁用旧的，避免 TTS 在窗口期内失败                                                                    |
| `LLM_API_KEY`           | DeepSeek 控制台新建 Key 后可先验证一次再删旧 Key                                                                             |
| `MP_APP_KEY`            | 虚拟支付后台重置后，下单签名立即切换                                                                                         |

## 5. 我负责做的

1. 读 `D:\mentorloop-secrets\rotation-2026-10-27.txt`，**不打印任何值**，只输出键名与长度校验。
2. 取云端全量 EnvParams（25 键），合并新值，删除 `MOCK_SMS_CODE` 与 `ALLOW_WEAK_SMS_CODE`。
3. 用 TC3 签名 `UpdateCloudRunServerConfig` 一次性回写（整包覆盖，先合并后写入，防丢键）。
4. `tcb cloudrun deploy` 发布新版本，使新变量生效。
5. 回读核验：键数、规格、访问策略、关键非密钥值。
6. 执行 §6 验证清单并出 `.gate.md`。
7. 删除本地密钥文件。

## 6. 验证清单

| #   | 验证项                         | 期望                                                                    |
| --- | ------------------------------ | ----------------------------------------------------------------------- |
| 1   | `GET /healthz`                 | 200，`driver=mysql`（证明新库密码可用）、`annotateFont=true`            |
| 2   | `POST /auth/wechat`（无 code） | 400「缺少微信身份凭证」（证明新 `WX_SECRET` 不阻塞登录入口）            |
| 3   | 服务端调微信接口               | `POST /resume/parse` 能正常取回云存储文件（证明 `WX_SECRET` 有效）      |
| 4   | `POST /interview/tts`          | 返回 `cloud://` fileID（证明新腾讯云密钥可用）                          |
| 5   | 完整简历评审                   | 200 且 `issues` 非空（证明新 `LLM_API_KEY` 可用）                       |
| 6   | 虚拟支付下单                   | `POST /membership/virtual/order` 返回签名参数（证明 `MP_APP_KEY` 有效） |
| 7   | 旧 token                       | 轮换 `JWT_SECRET` 后旧 token 一律 401（预期，用户需重新登录）           |

> 第 7 项是 `JWT_SECRET` 轮换的**必然副作用**：所有已登录用户（含开发者工具里的测试账号）需要重新微信登录。建议放在验证窗口的最后。

## 7. 回滚方案

| 场景                       | 回滚动作                                                                  |
| -------------------------- | ------------------------------------------------------------------------- |
| 部署后 `/healthz` 连库失败 | 立即回写旧 `MYSQL_PASSWORD` 并重新部署（新库密码在 TDSQL-C 侧需同时改回） |
| 微信相关接口 400/签名错    | 回写旧 `WX_SECRET`；旧值在公众平台重置后不可恢复时，重新生成一次并注入    |
| TTS 报鉴权失败             | 回写旧腾讯云密钥（旧的先别禁用，直到验证通过）                            |
| 任意项导致服务不可用       | 直接回滚到上一版本（`mentorloop-mp-api-046`）——旧版本仍持有旧变量         |

> 版本次序：新版本上线后，**上一个版本（046）保留旧值**，即天然的回滚点。确认稳定后再考虑彻底作废旧值。

## 8. 风险与对策

| 风险                                   | 等级 | 对策                                              |
| -------------------------------------- | ---- | ------------------------------------------------- |
| 改库密码与注入之间的窗口期服务连库失败 | 高   | 两者间隔控制在 5 分钟内；失败立即回滚 EnvParams   |
| 微信 Secret 重置后旧值不可逆           | 高   | 与部署贴紧；部署失败则立刻重新生成并再注入        |
| 整包回写 EnvParams 漏键导致配置丢失    | 高   | 先取全量、合并后再写；回读断言键数符合预期        |
| JWT 轮换导致全员掉线                   | 中   | 放在验证最后一步；MP 为微信登录，重登成本一次点击 |
| 新旧值混用导致部分接口半可用           | 中   | 一次部署统一切换，不逐项发版                      |
| 密钥文件留在磁盘                       | 中   | 用完即删；不进入仓库、不贴聊天                    |
