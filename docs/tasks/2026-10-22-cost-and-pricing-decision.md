# 任务卡：成本与定价决策（单位经济模型 + 定价红线）

- 日期：2026-10-22
- 关联：里程碑 M2「支付与会员」/ 父卡 [虚拟支付可行性](./2026-10-21-mp-virtual-payment-feasibility.md) / [W0 道具准备](./2026-10-22-mp-virtual-pay-w0-credentials-goods.md)
- 性质：**分析 + 决策卡**（本卡只产出结论与阈值，不改业务代码）
- 结论先行：**当前定价可持续，单场服务成本 ≈ 0.02 元、各 SKU 毛利率 > 94%；风险不在成本，而在会员「无限次」重尾、TTS 音色误配、以及固定成本结构。**

## 1. 目标

在 5 个道具发布前，用代码真实调用路径 + 官方现价建立单位经济模型，回答「现有定价能否支撑运转、会不会亏」，并把结论固化为可复算的公式、定价红线和重算触发条件，避免上线后靠感觉调价。

## 2. 范围

- 做：
  - 按代码取证每个付费动作的真实资源消耗（LLM 调用次数、TTS 字符数、存储与云托管用量）；
  - 按官方现价计算单场面试 / 单次简历评审的变动成本；
  - 计算 5 个 SKU 在 Android（1%）与 iOS（12%）下的毛利；
  - 盘点固定成本并给出盈亏平衡点；
  - 给出最坏 / 中性 / 理想三种情景；
  - 登记定价红线与「改价 / 换音色 / 换模型时必跑」的重算条件。
- 不做：
  - 不改 `skus.ts` 价格、不改任何业务代码或云端配置；
  - 不做获客成本（CAC）、留存与 LTV 建模（缺真实投放数据）；
  - 不做税务口径结论（需 LC/税务师确认）；
  - 不替 PO 决定最终价格（本卡只给区间与红线）。

## 3. 依赖

- 前置：W0 道具已按 `skus.ts` 价格发布（5 个道具 ID 与价格逐分一致）
- 外部环境：腾讯云 TTS 后付费单价、DeepSeek 定价页、微信云托管与 MySQL 计价、虚拟支付费率
- 契约：**否**（不改 `types/` / `api/` / 服务端出参）

## 11. 单位成本公式

```text
单场面试变动成本 = TTS成本 + 报告LLM成本 + 云托管算力 + 存储/流量
  TTS成本      = 播报字符数 / 10000 * 音色单价
                 标准模式 ≈ 300 字符（7 题 + 收束，题干 25–35 字）
                 深度模式 ≈ 560 字符（12 题 + 追问）
  报告LLM成本  = 输入token/1e6*1 + 输出token/1e6*2
                 约 800 进 / 800 出 → ≈ 0.0024 元
  云托管算力   ≈ 0.005 元（约 25 次请求，每次 50–200ms）
  存储/流量    ≈ 0（音频播完即删；简历仅留存至删除）

单次简历完整评审成本 = LLM + 解析CPU + 存储
  LLM ≈ 5000 进 / 1200 出 → ≈ 0.008 元；含解析与存储 ≈ 0.02 元
```

## 13. 固定成本与盈亏平衡

| 固定项                 | 元/月     | 说明                                         |
| ---------------------- | --------- | -------------------------------------------- |
| 云托管 MySQL           | 246       | 0.342×24×30；前 3 个月在免费额度内           |
| 云托管容器             | 10–30     | 最小副本 0，无访问不产生费用                 |
| 云存储 + 构建          | ~8        | 音频播完即删                                 |
| 短信（若启用真实短信） | ~20       | 0.04 元/条 × 500；当前为 mock 验证码，暂为 0 |
| LLM 预充               | ~10       | 按实际用量，正常月耗 < 5 元                  |
| **合计**               | **≈ 290** | MySQL 占约 85%                               |

**盈亏平衡：约 8 张月卡（Android）/ 9 张（iOS），或 2 张年卡。** 门槛极低，说明瓶颈是获客与转化，不是成本。

## 14. 定价红线与重算触发条件

| #   | 红线 / 触发条件                                    | 动作                                                  |
| --- | -------------------------------------------------- | ----------------------------------------------------- |
| 1   | 生产环境 TTS 音色不是精品音色                      | 阻断发布；回滚到 `101001`                             |
| 2   | 单场变动成本 > 售价的 5%                           | 触发重算（当前 0.02 / 9.7 = 0.2%，余量充足）          |
| 3   | 会员月度用量分布 P99 > 公平使用阈值                | 收紧阈值或引入超量计费                                |
| 4   | 官方单价变动（TTS / DeepSeek / 云托管 / 平台费率） | 用 §11 公式重跑 §12、§13，更新本卡并同步购买页文案    |
| 5   | 新增任何 LLM 调用点（如逐题反馈、实时追问生成）    | 先按 §11 补成本行，再评估定价；禁止无成本口径直接上线 |
| 6   | 新增按次计费的重资源能力（如批注版 PDF）           | 单独立卡算成本，不得用现有 SKU 兜底                   |
