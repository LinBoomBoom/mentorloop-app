# 任务卡：跨 tab 复盘域分段深链（「结果」tab 落点）

- 日期：2026-10-15
- 关联：里程碑 M1；承接 `2026-10-14-ia-consolidation.md`（IA-1）进度记录「未覆盖项 2：无跨 tab 分段深链」；链型 **微链**（实现 → G2）

## 1. 目标

让首页数据条「累计面试 / 平均等级」点进去**直达**「结果」tab 的成长趋势分段，消掉 IA-1 遗留的「先落到默认分段、还需再点一次」的多余操作。

## 2. 范围

- 做：
  - 新增模块级「待消费分段意图」`store/report-segment.uts`（写入 / 读取并清空）。
  - 首页数据条入口写入 `growth` 意图后跳「结果」tab。
  - 报告页 `onShow` 消费一次意图并切换分段。
- 不做：
  - 不改 tabBar 项数 / 文案 / 图标，不改 `pages.json`。
  - 不改 `types/`、`api/`、`server/`、`engine/`（**不触发契约冻结**）。
  - 不改报告页视觉与分段 UI（沿用 IA-1 已落地形态）。
  - 不改其他入口：首页「最近报告」卡仍落默认「本场报告」分段。
  - 不引入事件总线 / 全局 store 框架；不做跨 tab 的其他传参。

## 3. 依赖

- 前置：✅ IA-1 已交付（报告页页内分段已存在：`seg` 状态 + `showGrowth()`）。
- 外部环境：微信开发者工具 / 真机走查（tab 切换落点属交互，静态检查无法替代）。
- 契约：无（`types/`、`api/` 零改动）。

## 4. 验收标准

- [x] 首页「累计面试」「平均等级」点击后，落在「结果」tab **且分段为成长趋势**。
- [x] 首页「最近报告」卡片点击后，仍落在**本场报告**默认分段（意图不串门）。
- [x] 意图**一次性**：消费后清空；用户手动切回「本场报告」后来回切 tab，不会被动跳回成长趋势。
- [x] `store/report-segment.uts` 有对应单测（`tests/report-segment.spec.ts`，3 例）。
- [x] `pnpm lint` / `pnpm typecheck` / `pnpm test` / `check-uvue-css` / `check-design-tokens` 全绿。
- [ ] 真机走查勾选（人工环节，见 `2026-10-14-ia-consolidation.accept.md` 场景 D）。

## 5. 风险与对策

| 风险                                                        | 等级 | 对策                                                                 |
| ----------------------------------------------------------- | ---- | -------------------------------------------------------------------- |
| 意图未消费 → 下次进 tab 仍跳成长趋势（脏意图）              | 中   | `consume()` 读后立即清空；单测覆盖「消费后不再生效」                 |
| `switchTab` 复用已存在页面实例，`onShow` 触发时机与预期不符 | 中   | 走查覆盖「先看报告 → 回首页 → 点数据条」与「冷启动点数据条」两条路径 |
| 新增 store 文件与既有 store 约定不一致                      | 低   | 沿用 `training-history.uts` 的「类 + 导出单例」写法                  |
