# 任务卡：首页底部操作区重设计（home-cta）

- 日期：2026-10-16
- 关联：里程碑 M1；UX 台账 `docs/issues/2026-10-16-mp-ux-backlog.md` U1；链型 **标准链**（任务卡 G1 → 实现 → G2 → G3）

## 1. 目标

消除首页「底部操作区 + tabBar」双层底栏对首屏与滚动内容的挤压，把主 CTA 放回它真正属于的位置（首屏主任务卡内），使底部只剩 tabBar。

## 2. 现状（可复核）

`pages/index/index.uvue` L200–218：

```
<view class="px-5 pt-3" :style="{ paddingBottom: bottomPad + 'px', backgroundColor: 'rgba(11,33,56,0.9)' }">
  <view class="mt-3">                                  ← 与外层 pt-3 重复上边距
    <ml-button text="开始模拟面试" type="primary" block />
  </view>
  <view v-if="!loggedIn" class="... mt-2.5 h-11" ...>   ← 未登录时再 +44px
    登录后同步训练记录与报告
  </view>
</view>
```

- 底部占用估算：`pt-3(12) + mt-3(12) + 按钮(≈44) + [登录行 h-11(44) + mt-2.5(10)] + bottomPad(24 或 safeArea+10)` ≈ **110–170px**，其下还有 tabBar **68px** → 合计最高约 240px，占 iPhone 12/13（844px）近三成。
- 该操作区**在文档流内**，但带 `rgba(11,33,56,0.9)` 深色底 → 视觉上是一条压住内容的浮条；`scroll-view` 内层仅 `pb-5`(20px)，与操作区高度无关，内容末尾直接贴住它。
- 结论：用户的"按钮展位太多、遮盖滚动内容"成立，根因是**位置（应在主任务卡内）+ 冗余高（重复边距与次要行）+ 视觉权重（0.9 深色底）**三者叠加。

## 3. 范围

- 做（**决策：方案 B1**，见 §4）：
  - 把主按钮「开始模拟面试」移入首屏「本次模拟面试」参数卡内（卡内底部，`block`，`primary`）。
  - 删除底部操作区整个容器（含未登录提示行）。
  - 未登录提示降级为参数卡内按钮下方一行 12px 文字（可点，非 44px 行高），保留可见性但不再占一整个按钮位。
  - 底部只剩 tabBar；`scroll-view` 内层底部留白按需微调（不再需要为浮条预留）。
- 不做：
  - 不改 tabBar 项数与文案；不改 `pages.json`。
  - 不改 `ml-button` 组件本身的规格（避免波及其它页面）。
  - 不改首页信息结构（参数卡 / 简历入口 / 数据条 / 最近报告 的位置与顺序）。
  - 不做悬浮胶囊（方案 B3）——登记为备选，若上线后实测「主 CTA 常驻」是刚需再启用。
  - 不动 `types/`、`api/`、`server/`、`engine/`（**不触发契约冻结**）。

## 4. 方案对比与决策

| 维度             | **B1 卡内 CTA（决策）**                  | B2 底部条瘦身（备选）    | B3 右下悬浮胶囊（备选）          |
| ---------------- | ---------------------------------------- | ------------------------ | -------------------------------- |
| 位置             | 首屏主任务卡内                           | 仍为流内底部条           | tabBar 上方右侧悬浮              |
| 底部净释放       | **≈110–170px**（只剩 tabBar）            | ≈44–110px                | ≈50px 仍需避让                   |
| CTA 常驻可见     | ❌ 滚过首屏后不可见                      | ✅                       | ✅                               |
| 与首屏语义一致性 | ✅ 参数与其动作同卡，读完即点            | 中                       | 中（浮层与内容无关联）           |
| 改动面           | `index.uvue` 局部（删一段 + 卡内加一行） | `index.uvue` 局部        | 较大（浮层定位 + 避让 + 安全区） |
| 主要代价         | 常驻性丢失（首屏仅约 1.2 屏，影响有限）  | 底栏仍是双层，视觉未根治 | 多一层浮层，遮挡风险回到"浮"     |

**决策理由**：U1 的根因是"位置错"，B1 直接纠正位置并一举释放底部空间；B2 只治高度不治位置；B3 把遮挡问题换成另一种遮挡。常驻性损失可控（首页内容短，且 tabBar 已有「专项训练」承接）。

## 5. 验收标准

- [ ] 首页底部不再存在带深色底的常驻操作区；底部仅 tabBar。
- [ ] 「开始模拟面试」按钮位于首屏参数卡内，滚动到首屏即可见、可点，行为与改动前一致（进 prep）。
- [ ] 未登录提示不再占用整行 44px；点击仍能触发登录动作。
- [ ] 滚动到底部时，最后一张卡与 tabBar 之间有可见呼吸空间（≥12px），无内容被压住。
- [ ] 小屏（iPhone SE 375×667 预览）首屏可见内容增加，无横向/纵向溢出。
- [ ] 首页既有断言不回归：E2E `IA1-B1/B2/B3/B4/B5` 仍全绿（参数卡内 CTA 不影响这些入口）。
- [ ] `pnpm lint` / `pnpm test` / `pnpm build:mp-weixin` 全绿；改动前后各留一张首页截图对比。

## 6. 风险与对策

| 风险                                    | 等级 | 对策                                                             |
| --------------------------------------- | ---- | ---------------------------------------------------------------- |
| 常驻 CTA 消失导致"开始面试"入口曝光下降 | 中   | 上线后看首页 CTA 点击率；若劣化则切 B3 悬浮胶囊（备选已留痕）    |
| 参数卡内加按钮后卡片过高，首屏仍需滚动  | 中   | 同时删除简历入口与数据条之外的重复留白；用截图对比确认首屏信息量 |
| 未登录提示降级后曝光不足，登录转化下降  | 低   | 保留可点；并在「我的」页保留原有登录入口（已存在）               |
| 与 U2（首启画像）同改首页导致改动面交叉 | 低   | 两卡分开提交；若并行，先合 U2 再合本卡，避免冲突                 |
