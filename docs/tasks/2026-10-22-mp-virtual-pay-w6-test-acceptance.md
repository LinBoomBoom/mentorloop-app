# 任务卡：W6 虚拟支付测试与验收

- 日期：2026-10-22
- 关联：里程碑 M2「支付与会员」/ 父卡 [2026-10-21-mp-virtual-payment-feasibility.md](./2026-10-21-mp-virtual-payment-feasibility.md) §12 W6

## 1. 目标

端到端验证「下单 → 拉起 → 推送 / 查单 → 发放 → 对账」闭环，并通过 G2 质量门。

## 2. 范围

- 做：
  - 签名单测、回调幂等与三元校验测试；
  - 小额真单（最低价道具）；
  - 订单与账本对账；
  - mock 模式回归；
  - G2 门禁与验收记录。
- 不做：
  - 不做压力测试；
  - 不做多商户 / 分账；
  - 不做 iOS 退款实操（退款由 Apple 决定，仅验证通知处理）。

## 3. 依赖

- 前置：W3 / W4 / W5
- 外部环境：W0 全部就绪（含道具生效 ≥ 10 分钟）
- 契约：否

## 4. 验收标准

- [x] 服务端单测全绿（含新增签名、回调、查单用例）
- [x] 真单支付成功 → 推送落账 → 权益发放 → 账本一致（Android `test_pay_01`；iOS 待正式版）
- [x] 重复推送与伪造推送均不重复发放（14 例推送单测 + 云端模拟推送回包）
- [x] mock 模式回归通过
- [ ] App 端 v3 JSAPI 回归通过（下单带 `platform='app'`）
- [x] 生产云端 `MP_PAY_MODE=virtual` 已回读（禁止以默认 `mock` 上线）
- [x] G2 门禁通过并产出 `.gate.md`
- [x] 验收记录产出 `.accept.md`，含真单号（脱敏）与时间戳

## 5. 风险与对策

| 风险                 | 等级 | 对策                                                  |
| -------------------- | ---- | ----------------------------------------------------- |
| 真单金额与月限额     | 低   | 用最低价道具（2900 分），单账号单日 ≤ 2 笔            |
| 虚拟支付无沙箱       | 中   | `env` 现网只能为 0（父卡 b2），真单即现网，先小额验证 |
| 回调延迟导致误判失败 | 中   | 以服务端账本为准，客户端不本地发放                    |
