# 任务卡：购买前绑定手机号（服务端端点 + 客户端绑定流程）

- 日期：2026-10-23
- 关联：P1.3 会员/虚拟支付；设计稿 [2026-10-23-phone-binding-mockup.html](../design/2026-10-23-phone-binding-mockup.html)（2026-10-23 评审通过）；今日报告待办 #1/#2

## 1. 目标

小程序静默登录账号在购买会员/加量包前完成手机号绑定，让权益发放与售后有可核验凭证，且绑定始终归属当前 uid（不切号、不覆盖他人账号）。

## 2. 范围

- 做：
  - 新增 `GET /me/phone`、`POST /me/phone`（绑定到当前登录 uid）
  - 下单前置校验：未绑定手机号的账号拒绝创建订单
  - 客户端绑定接口 + mock；支付页未绑定 → 绑定半屏层 → 绑定成功后继续支付
  - 账号与安全页展示脱敏手机号，并可进入更换流程
  - 服务端单测覆盖绑定成功 / 幂等 / 冲突 / 验证码错误 / 未绑定下单
- 不做：
  - 不做原手机号释放、账号申诉迁移（冲突按设计稿走客服）
  - 不把手机号作为小程序登录凭证（MP 仍 openid 静默登录）
  - 不做第三方绑定、设备管理
  - 不改 App 端手机号验证码登录

## 3. 依赖

- 前置：设计稿已评审通过；`/auth/sms-code` 已上线
- 外部环境：无新增密钥；MP 侧需体验版真机验证
- 契约：是（`api/` 与服务端出参变更），已出冻结单 [2026-10-23-phone-binding.freeze.md](../contracts/2026-10-23-phone-binding.freeze.md)

## 4. 验收标准

- [ ] MP 静默登录账号在支付页点击购买 → 弹出「绑定手机号」半屏层；未绑定不得下单
- [ ] 手机号 + 验证码绑定成功 → 自动继续支付；`userStore.profile.phone` 写入并持久化
- [ ] 手机号已属于其他账号 → 服务端 409（业务码 40901），页面提示更换手机号或联系客服，原账号不被覆盖
- [ ] 未绑定账号直接调用 `POST /membership/order` → 409（业务码 40902），不产生订单
- [ ] 账号与安全页显示脱敏手机号（如 138****1234），可进入更换流程
- [ ] 服务端新增单测通过；G2 客户端与服务端门禁全绿

## 5. 风险与对策

| 风险                     | 等级 | 对策                                                         |
| ------------------------ | ---- | ------------------------------------------------------------ |
| 同一手机号并发绑定竞争   | 中   | 事务内条件更新 + 占用回查，失败返回冲突                      |
| 已绑定用户重复提交       | 低   | 本人已绑定 → 幂等 200；客户端按钮 loading 防重复             |
| 下单前置校验误伤存量用户 | 中   | 存量测试均走手机号登录（phone 非空），已核查三个支付测试文件 |
| 验证码爆破               | 中   | 复用 `sms_codes` 一次性消费 + 绑定失败限流                   |
| 绑定后 uid/token 被切走  | 高   | 绑定只 UPDATE 当前 uid，不新建账号、不签发新 token           |
