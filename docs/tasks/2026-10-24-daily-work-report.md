## 3. 今日补充的系统规则（用户定版）

1. **汇报格式**：用户说「总结 / 汇报」时，必须产出当日任务完成情况 + 当日遇到的问题与解决思路，落 `docs/tasks/YYYY-MM-DD-daily-work-report.md`。
2. **设计先行**：任何页面改造 / 排版优化必须先出设计图（落 `docs/design/`），参考主流产品优秀案例与 GitHub 优秀开源设计，配合 UI 设计 skill；设计稿评审通过后才能编码。
3. **目标人群与设计基调**：面向学生、实习生、跳槽人群、跨专业学习人群（20–35 岁）；设计重细节、有质感、主次清晰、业务逻辑不混乱，始终围绕「面试训练 / 能力成长」主题。
4. **UI 设计只出 HTML**：不再导出 PNG/JPG 设计图，评审直接打开 HTML。
5. **原生 tabBar 三等分**：不浮 FAB、不挤占 tab；主行动放回页面内容。中央主行动只能走 uni-ui x `uni-tab-bar` 的架构级改造。
6. **留白是设计**：不得用装饰性图表 / 趋势卡 / 假入口填空；只设计系统已支持的功能，超前项必须标注「超前 · 未实现」。
