# 任务卡：设备检测去伪 + 录音/发声链路自检

- 日期：2026-10-22
- 关联：里程碑 M3（语音面试能力补全）；承接 [系统问题清单](./2026-10-21-system-issue-inventory.md)；用户 2026-10-22 真机反馈「没有成功录音和发声」

## 1. 目标

把准备页「设备检测」从「接口没报错」升级为「真的采到音频、真的播得出来」，并修掉检测残留监听会在 800ms 后掐断房间录音的缺陷。

## 2. 范围

- 做：
  - 麦克风检测：录音后校验 `tempFilePath` 非空且文件字节数 > 0，不再以 `onStop` 触发即通过。
  - 新增「扬声器」检测项：回放刚录的音频，`onEnded` 才算通过（同时覆盖「发不出声」）。
  - 检测结束注销 `RecorderManager` 的 `onStart/onStop/onError` 监听，并清理计时器。
  - 小程序端播放前调用 `setInnerAudioOption({ obeyMuteSwitch: false })`，消除 iOS 静音键导致的无声。
  - 房间录音结束后做文件自检，把「没有录到音频」与「转写为空」拆成两条不同提示，并落日志。
- 不做：不改服务端 ASR / TTS 驱动与路由；不改 `types/` 与任何请求/响应契约；不新增音频资源文件；不做录音振幅/波形的实时驱动；不动 Android 原生录音增强（`interviewer-audio`）。

## 3. 依赖

- 前置：微信 `getRecorderManager()` 为全局单例且支持 `offStart/offStop/offError`；`InnerAudioContext.src` 支持本地临时文件路径；`FileSystemManager.getFileInfo` 可读临时文件大小。
- 外部环境：MP 真机（录音 + 回放 + 静音键）；云端 TTS/ASR 凭据状态不影响本卡（本卡只做客户端自检与提示）。
- 契约：**不涉及**。无 `types/` 字段变更、无 `api/` 出入参变更、无服务端出参变更；`api/speech.uts` 仅改内部播放前置行为。

## 4. 验收标准

- [ ] 点「开始检测」后四项依次真实执行：网络、录音授权、麦克风、扬声器。
- [ ] 麦克风通过条件 = `tempFilePath` 非空 **且** 文件字节数 > 0；读取大小失败（返回 -1）时不据此判失败。
- [ ] 检测结束（成功/失败/超时）后，本次注册的 `onStart/onStop/onError` 全部注销；随后进入房间录音不会被检测逻辑提前 `stop()`。
- [ ] 扬声器项只有在回放 `onEnded` 时才置「已通过」；`onError` 或 8s 超时置未通过并给出可执行提示。
- [ ] iOS 打开静音键时，小程序内回放与面试官念题仍能出声。
- [ ] 房间录音为空或文件 0 字节 → 提示「没有录到音频…」；录音有效但转写为空 → 保留「没有听清你的回答…」，两者不混淆。
- [ ] G2 通过：lint / format / 单测 / `build:mp-weixin`。

## 5. 风险与对策

| 风险                                    | 等级 | 对策                                                                                  |
| --------------------------------------- | ---- | ------------------------------------------------------------------------------------- |
| 回放用户自己的录音被误解为「泄露/诡异」 | 中   | 仅在「下载/检测」动作内回放，不落盘、不上传、文件随临时目录回收；文案明确「回放试音」 |
| 安静环境下录音文件极小被误判为空        | 低   | 只把 0 字节判为失败；非 0 字节一律放行，转写结果另走既有降级                          |
| `offStart` 在低版本基础库不存在         | 低   | 调用包 `try/catch`，注销失败不阻塞流程（监听泄漏仅影响本次会话）                      |
| 检测中途离开页面导致计时器泄漏          | 低   | 统一 `finish()` 收口，所有分支清理计时器与监听                                        |

## 9. 开工前质询（未决项清单）

| #   | 质询                                              | 结论                                                                                                                              |
| --- | ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `RecorderManager` 是否单例、监听能否注销？        | 已查证：微信官方 `wx.getRecorderManager()` 返回全局唯一实例，`RecorderManager` 提供 `offStart/offStop/offError`（按回调引用注销） |
| 2   | 录音临时文件能否被 `InnerAudioContext` 直接播放？ | 已查证：`InnerAudioContext.src` 支持本地文件路径与 `cloud://` fileID 两种来源                                                     |
| 3   | iOS 静音键是否会让小程序音频无声？                | 已查证：`setInnerAudioOption` 的 `obeyMuteSwitch` 默认 `true`（跟随系统静音键），需显式置 `false`                                 |
| 4   | 0 字节与「安静但有效」的录音如何区分？            | 已决策：仅 `size === 0` 判失败；`getFileInfo` 不可用返回 `-1` 视为未知，不据此判失败                                              |
| 5   | 是否新增埋点事件名？                              | 已决策：复用既有 `interview_asr_fallback`，追加 `reason='record_empty'` 属性，不改 `types/tracking.uts`，不触发契约冻结           |
