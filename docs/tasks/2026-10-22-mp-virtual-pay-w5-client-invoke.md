# 任务卡：W5 客户端虚拟支付拉起

- 日期：2026-10-22
- 关联：里程碑 M2「支付与会员」/ 父卡 [2026-10-21-mp-virtual-payment-feasibility.md](./2026-10-21-mp-virtual-payment-feasibility.md) §12 W5

## 1. 目标

MP 端按 SKU 拉起虚拟支付，正确处理成功 / 取消 / 失败 / 版本不支持 / session_key 过期。

## 2. 范围

- 做：
  - `#ifdef MP-WEIXIN` 新增虚拟支付分支，`globalThis.wx.requestVirtualPayment`；
  - `wx.canIUse('requestVirtualPayment')` 判基础库 ≥ 2.19.2；
  - iOS 微信版本判定（先做 f1 POC）；
  - 下单请求按平台带 `platform`（`App='app'`，`MP='mp-weixin'`）；
  - -15007 自动 `wx.login` 重登并重试一次；
  - 识别服务端 409（`session_key` 缺失 / 过期）并执行「重登 → 重试一次」；
  - 失败码提示与支付后 `fetchQuota` 对账。
- 不做：
  - 不改 App 端 `requestWxPay`；
  - 不做代币 / 订阅；
  - 不做支付 UI 改版。

## 3. 依赖

- 前置：W1a + W1b（契约结构与取值）
- 外部环境：iOS 真机（微信 ≥ 8.0.68）、Android 真机
- 契约：是（按 W1a 冻结单实现）

## 4. 验收标准

- [ ] iOS 与 Android 真机各成功拉起一次（真机待验）
- [x] 成功 / 取消 / 失败三态：取消（-2）静默、失败按冻结单 §5.2 文案、成功后才对账与埋点（代码级）
- [x] 基础库 < 2.19.2 明确提示且不崩溃（`wx.canIUse('requestVirtualPayment')` 前置）
- [x] -15007 自动重登重试一次，仍失败则提示重试（另有服务端 409 同路径）
- [x] `POST /membership/order` 请求含 `platform`（MP=`mp-weixin`；App=`app`）
- [x] App 端下单请求带 `platform='app'`，v3 JSAPI 回归通过
- [x] f1 结论落盘：**官方文档已给出示例**（`wx.getSystemInfoSync().version` + `platform`），无需自研 POC

## 5. 风险与对策

| 风险                   | 等级 | 对策                                                            |
| ---------------------- | ---- | --------------------------------------------------------------- |
| 低版本基础库无接口     | 中   | `wx.canIUse` 前置判断 + 明确文案                                |
| iOS 无法可靠读微信版本 | 中   | f1 POC 先收口；不可读则降级为接口探测（canIUse + 调用失败提示） |
| -15007 循环重试        | 中   | 仅重试一次，记录并提示                                          |
| 支付成功但回调延迟     | 中   | 支付后 `fetchQuota` 对账，不做本地直接发放                      |
