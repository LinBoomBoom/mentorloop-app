# 任务卡：首次进入画像引导（onboarding）

- 日期：2026-10-16
- 关联：里程碑 M1；UX 台账 `docs/issues/2026-10-16-mp-ux-backlog.md` U2 + U3；链型 **标准链**（任务卡 G1 → 实现 → G2 → G3）

## 1. 目标

让用户**首次进入就先行选择岗位方向与经验年限**，并让首页参数卡从"显示别人的默认值"变为"显示用户自己的画像"，同时把改参数的成本从「开始面试 → prep 多一步」降到「点一下参数卡」。

## 2. 范围

- 做：
  - 新增首启引导页 `pages/onboarding/onboarding.uvue`：① 岗位方向（复用 `POSITION_OPTIONS`，`available=false` 的置灰 +「敬请期待」）② 经验年限（复用 `EXPERIENCE_OPTIONS`）③ 明确的「跳过」入口。
  - 触发：首页 `onShow` 判定 `userStore.profile.onboarded !== true` → 跳转引导页（`navigateTo`，非 tab）。
  - 提交：写入 `positionId` / `experienceLevel` 并置 `onboarded = true`（本地持久化）→ 返回首页；埋点 `onboarding_complete` / `onboarding_skip`。
  - 跳过：写入默认值但 `onboarded = false` 不成立 → 视为已引导（`onboarded = true`）但首页参数卡标注「未设置 · 点此选择」，不得伪装成用户已选。
  - 修 U3：首页参数卡整卡可点 → 复用同一页做「修改面试参数」；页内标题按来源切换（首启 / 修改）。
- 不做：
  - 不新增 tab，不改 tabBar；不改 `pages.json` 既有条目属性以外的东西。
  - 不强制登录、不做注册墙（免费层钩子不能被前置表单挡住）。
  - 不做简历导入/解析（另卡）。
  - 不改 `types/`、`api/`、`server/`（`UserProfile` / `UserProfilePatch` 定义在 `store/user-profile.uts` 内，属客户端本地结构，**不触发契约冻结**）。
  - 不改首页视觉体系（沿用既有 token 与浅色面语汇）。

## 3. 依赖

- 前置：无（纯客户端）。
- 外部环境：微信开发者工具 + 自动化 E2E（`e2e/mp/`，可写断言）。
- 契约：**无**（见 §2「不做」第 4 条）。

## 4. 验收标准

- [ ] 清空本地存储后首次进首页 → 进入引导页；选择并提交后落首页，参数卡显示所选岗位/年限。
- [ ] 选择「跳过」→ 落首页，参数卡标注「未设置 · 点此选择」，且不显示为已选中的具体值。
- [ ] 再次启动（`onboarded === true`）→ 不再自动进引导页。
- [ ] 首页参数卡可点 → 进同一页做修改；改完回首页参数同步更新。
- [ ] `available === false` 的方向不可选，点击给出「题库建设中，敬请期待」反馈（与 prep 一致）。
- [ ] 埋点：`onboarding_complete` / `onboarding_skip` 各上报一次，参数含所选项。
- [ ] 五态覆盖：引导页具备空态（无可用方向时的兜底）与错误态（存储写入失败不阻断流程）。
- [ ] E2E 增加 1 条断言（引导页可达 + 提交后参数卡文案变化）；`pnpm lint` / `pnpm test` / `pnpm build:mp-weixin` 全绿。

## 5. 风险与对策

| 风险                                           | 等级 | 对策                                                                     |
| ---------------------------------------------- | ---- | ------------------------------------------------------------------------ |
| 前置表单伤首启转化（与"免费层钩子"冲突）       | 高   | 必须提供「跳过」；跳过不阻断任何浏览与免费功能；上线后看首启完成率与流失 |
| 判断字段写入失败导致每次启动都进引导页（循环） | 中   | 存储失败时本次会话内存标记为已引导，不重复弹；错误态不阻断               |
| 与 prep 页的岗位/年限选择出现两套交互          | 中   | 抽同一份选项数据（`data/position-options.uts`）；文案与置灰规则对齐 prep |
| 引导页与参数卡"未设置"语义不一致               | 低   | 文案与状态由单一字段 `onboarded` 驱动，不另设中间态                      |

## 6. 产物路径

## 9. 开工前质询（未决项清单）

| #   | 质询                           | 结论                                                                                                                                      |
| --- | ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 是真缺页面，还是缺"前置时机"？ | **查证：选择能力已存在于 `pages/interview/prep.uvue` L13–88**，缺的是首启时机与参数卡可编辑入口。                                         |

| 5   | 与 prep 的重复如何避免？       | 共用 `data/position-options.uts`；置灰与 toast 文案与 prep 对齐；不复制第二套选项常量。                                                   |
