## 3. 产品方案

参考 LeetCode（topic + difficulty）、牛客题库（方向分层）、Anki（自评驱动复习）、Duolingo（掌握度路径）、极客时间每日一题（轻量节奏）。最终形态：

**方向 → 细分领域 → 难度 → 题量 → 做题 → 自评 → 掌握度 / 错题 / 今日复习**

关键取舍：

- 题库是开放题，**不做选项化改造**（成本高且失真）；用「先想后看解析 + 自评」保留训练价值，同时得到可追踪掌握度。
- 当前解析使用既有 `expectedEvidence`，明示「参考解析 · 节选」，完整答案列入 Phase 2.2。
- 掌握度与错题先本地，Phase 2.1 升级为服务端权威 + 离线补传。

完整方案见 [做题模式方案](../design/2026-10-23-practice-mode-proposal.md)。

## 4. 技术实现

### 4.1 服务端

- 取题：`loadCandidates` 动态拼 `subtrack` / `difficulty` 过滤；传 `difficulty` 时把选择器经验档置为 `senior`，只让精确难度生效；旧调用行为不变。
- 记录：`practice_records`（用户 × 题唯一），SQLite 自举 + 云端 MySQL 启动迁移幂等建表。
- SRS：不会 1 天、模糊 1 天不降间隔、会按 1/2/4/7/15/30/60 天递进。
- 端点：`POST /practice/records`、`GET /practice/records|summary|wrong|due`，全部 `requireAuth`。
- 幂等：重复提交不重复计数；`answeredAt` 早于 `updated_at` 的补传被忽略。

### 4.2 客户端

- 做题页：4 方向 chip、细分领域单列（含本机/云端「已做 · 会」）、难度段、题量、固定底部「开始做题」、错题本与今日复习入口。
- 做题房间：题目卡 → 组织答案提示 → 查看参考解析 → 自评 → 下一题 → 本组小结；错题/到期复习复用同一房间（`mode=wrong` / `mode=due`）。
- 同步：`pending` 队列（≤200）离线补传；登录后拉服务端汇总/错题覆盖本地；训练页 `onShow` 先本地后云端。
- 解析：客户端做 Markdown 纯文本化（去围栏、`**`、反引号，列表符转「·」）。
