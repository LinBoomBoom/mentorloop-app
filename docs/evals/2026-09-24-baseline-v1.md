## 1. 基线（Baseline v1）

以 2026-09-24 固定评测集 v1.0.0 全绿运行为基线：

| 层             | 用例数 | 断言类型                                                  | 基线结果 |
| -------------- | ------ | --------------------------------------------------------- | -------- |
| 元信息         | 1      | 版本与冻结日期                                            | ✅ 通过  |
| 选题 selection | 5      | 结构性（意图 / 深度 / 维度覆盖 / 置信区间）               | ✅ 5/5   |
| 追问 followup  | 7      | 结构性（wrapup / 意图 / 深度上限 / 维度）                 | ✅ 7/7   |
| 评分 scoring   | 2      | 结构性（维度数 / 等级落在量表 / 置信区间 / 训练计划条数） | ✅ 2/2   |
| 合计           | 15     | —                                                         | ✅ 15/15 |

执行方式：`pnpm test`（vitest，`tests/evals/eval.spec.ts`）。

## 2. 阈值（Merge Threshold）

- **结构性断言 100% 通过方可合入**（15/15，零容忍）。任一用例回归 → 阻断合入，回退或修复后重跑。
- 评测报告（`assets/eval-report-template.md` §3）中「基线 / 本次 / 阈值」三列：本次 = 基线 = 全绿为通过。
- v1 阈值为**纯结构性**（不评文案质量）。语义质量（追问是否自然、解释是否准确）由 §3 人工抽检兜底，不设自动阈值。

## 3. 人工抽检制度（Manual Sampling）

触发时机：**每次评分量表或选题规则变更合入前**（与固定评测集回归同批执行）。

执行人：**CO + AI 双人**（AI 出具初检，CO 复核留痕）。

抽检量与判定：

| 层   | 抽检量   | 抽检内容                                   | 判定依据                      |
| ---- | -------- | ------------------------------------------ | ----------------------------- |
| 选题 | 3 条用例 | 选题是否符合能力图谱与岗位画像             | `data/ability-map` + 选题规则 |
| 追问 | 2 份转写 | 深度 ≤ 2 层、意图正确、无羞辱/隐私探测     | 评分量表 + 追问规则           |
| 评分 | 2 份报告 | 维度等级是否落在量表锚点、置信区间是否诚实 | 评分量表锚点                  |

记录方式：结论写入评测报告 §4 人工抽检表（用例 / 抽检人 / 结论 / 备注），**抽检不通过 = 不得合入**，与结构性断言同权。

## 4. 变更纪律

- 评测集用例本身变更 → 升版本号（v1.x）+ 更新本基线文档 + 重新冻结日期。
- 阈值收紧（如加入语义评分）→ M2 后按实测分布另立 v2 基线，不在本文件内追加。
