## 1. 文档研读结论（7 份文档基线摘要）

### 1.1 产品定位（01）

- 移动端 AI 面试训练产品：简历/岗位 → 能力画像 → 个性化题目路径 → 数字人语音面试与动态追问 → 证据化评分报告 → 专项训练 → 复测对比的**能力闭环**，不是题库播放器或聊天机器人。
- 首发人群：1–3 年经验 Java 后端求职者；首发**不做**真人撮合、简历代投、社区、第三方视频数字人。
- 差异化：面试证据链、有职业人格的数字人、岗位化、训练闭环、移动场景优先。
- 商业模式：免费层 / 单次包 / 订阅会员 / B 端席位。
- 北极星指标：完成一次正式模拟面试的用户数、面试完成率、报告查看率、报告后 7 日训练完成率、14 日再次模拟率、付费转化率与单场面试综合毛利。

### 1.2 功能模块与 AI 面试引擎（02）

- 五大功能模块：入职画像与岗位蓝图、AI 数字人面试（快练 5 / 标准 20 / 深度 40 分钟）、题库与专项训练、AI 简历优化、报告与成长档案。
- 面试引擎五层独立设计：岗位能力图谱 → 题目选择器 → 追问策略（澄清/证据/深挖/反例/迁移/收束六类意图，单知识点最多深挖两层，禁止羞辱性与隐私追问）→ 评分引擎（量表+证据+校准，六维度权重 25/25/20/15/10/5，低置信度不伪装精确分数）→ 报告生成器（结构化数据先行，LLM 只做解释，不得篡改证据与分数）。
- 数字人：2.5D 半身面试官，TTS→音素→口型→表情状态机→姿态→渲染；空闲/提问/倾听/追问/总结五种状态；声音克隆默认不做。

### 1.3 UI/UX 规范（03）

- 体验原则：降低焦虑不降低标准、任务优先于装饰、反馈可解释、单手可用、隐私透明。
- 视觉：深海军蓝 `#0F2C4C`（面试房间）、紫蓝 `#5B6CFF`（智能状态）、青绿 `#1FB6A6`（完成/可靠）、浅底 `#F7F9FC`；正文 14–16px、关键结论 ≥18px；动效仅表状态且尊重"减少动态效果"。
- 硬交互规则：面试结束二次确认、异常退出自动保存、**不显示实时评分**、跳过保留为证据、低分点可展开原始转写与锚点、AI 改写一律标"建议稿"、虚构数据醒目标记、提供简历/录音/转写/账户自助删除。
- 无障碍：字幕、文字模式、语速/音量控制、高对比度、不仅用颜色表达状态、录音降级体验与评分说明。

### 1.4 技术架构（04）

- uni-app x 单代码库：70–80% 业务跨端复用；四个 UTS 原生插件（`interviewer-audio` / `interviewer-realtime` / `interviewer-avatar` / `interviewer-device`）隔离实时音频、数字人渲染、设备权限。
- 服务端：网关/认证、会话编排、画像题目追问、评分报告、简历解析、内容运营后台、支付/消息/埋点/风控。
- 面试状态机：`CREATED → DEVICE_CHECK → READY → ASKING → LISTENING → TRANSCRIBING → FOLLOW_UP_DECISION → NEXT_QUESTION|WRAP_UP → REPORT_GENERATING → COMPLETED`；事件必须带 `sessionId/questionId/eventSeq/idempotencyKey`；任何异常不得静默丢失答案。
- 性能规则：音频帧/口型不进响应式状态；UI 每秒仅同步 10–15 次摘要；单活跃数字人实例、退出即释放；虚拟滚动/分页；数字人资源分包；设备端不做大模型推理。
- 隐私安全：敏感数据分级存储、默认不用原始录音训练、TLS+字段加密、最小权限+审计、提示词注入与刷接口防护。
- 发布门槛：两周 POC（三端发布、录音/流式转写/TTS/弱网、口型同步 20 分钟、前后台/来电/蓝牙/权限）；正式验收（真机全覆盖、20 分钟无崩溃无内存增长无答案丢失、限流熔断监控、模型人工评测集验收）。

### 1.5 交付与协同（05）

- 里程碑：M0 立项与预研（第 1–2 周）、M1 可用原型（第 3–8 周）、M2 商业 MVP（第 9–18 周）、M3 上线与增长（第 19 周起）。
- 角色：产品负责人、UI/UX 设计师、客户端工程师、后端工程师、AI 工程师、QA/DevOps、内容运营（小团队 4–5 人兼任，但 QA、题库审核、AI 评测责任不可省略）。
- 多 Agent 协同铁律：AI Agent 不能单独决定产品规则；客户端与后端**先冻结接口契约再并行**；模型或评分规则变更必须运行固定评测集；发布必须由 QA/安全 Agent 给出准入结论。
- 每项任务卡必须包含：目标、范围、依赖、验收标准、风险、产物路径、负责人。

### 1.6 预算与合规（06）

- 推荐按 90 万元安排首阶段（研发 50 / 开办合规 8 / 设备题库测试 5 / 云与 AI 7 / 运营获客 10 / 风险金 10）。
- 上线合规清单：主体与经营范围、ICP/公安/App 备案、隐私政策与删除入口、SDK 与个人信息收集清单、存储期限与删除机制、生成式 AI/深度合成/算法备案评估、渗透测试与应急预案、支付与税务方案。
- 成本控制：云端 ASR/TTS/LLM 优先不仓促自建；以"每场面试综合毛利"做成本决策；风险金 ≥10–15%。

### 1.7 已冻结关键决策（00，不得随意变更）

微信小程序优先 + 同库 Android/iOS（App Beta 跟随）；自研 2.5D 数字人不采购 SaaS；AI 引擎独立设计；首发 Java 后端 1–3 年；业务跨端统一 + UTS 插件隔离平台差异。

## 6. 质量保障与进度跟踪机制

### 6.1 质量门禁（每次提交/每日）

- `pnpm check`（lint + typecheck + test）+ `scripts/check-uvue-css.mjs`（拦截 gap/space-*）；husky 提交前强制执行。
- CI（GitHub Actions）：install → lint → format → uvue CSS guard → test → typecheck → audit。
- 性能验证一律使用 **release 包**，禁止以 debug 模式或模拟器流畅度作为验收依据（文档 04 §1、README）。

### 6.2 评审节奏

| --------------------- | ----------------------------------------------- | ---------- | -------------------------- |

### 6.3 任务卡规范（文档 05 §3，强制）

每项任务必须包含：**目标、范围、依赖、验收标准、风险、产物路径、负责人**；缺项不得进入迭代。

## 7. 规范遵循清单（全员强制，评审时逐项核对）

### 7.1 编码规范（README §5 + engineering-toolchain-plan）

- [ ] 全部页面/组件 `<script setup lang="uts">` 组合式；禁止选项式与 mixin。
- [ ] UTS：`type` 不用 `interface`；空值用 `null` 不用 `undefined`；对象字面量 `as NamedType`；强类型。
- [ ] uvue：文字必须 `<text>` 包裹；`view` 默认纵向 flex；单位 rpx；禁止 gap/space-*、复杂后代选择器、Tailwind 透明度修饰符。
- [ ] 提交按模块单独 commit，Conventional Commits。

### 7.2 产品与体验规范（文档 02/03）

- [ ] 面试房间不显示实时评分；跳过保留为证据；结束二次确认；异常自动保存。
- [ ] 追问深挖 ≤2 层；禁止羞辱性、循环、隐私追问。
- [ ] 评分必须引用证据；低置信度不伪装精确分数；报告生成不得篡改原始证据与分数。
- [ ] AI 改写标"建议稿"；疑似虚构数据醒目标记。
- [ ] 无障碍：字幕/文字模式/语速/高对比度；不仅用颜色表状态。

### 7.3 隐私与安全规范（文档 04 §5、文档 06）

- [ ] 录音/上传状态可见；存储期限与删除入口可用（简历/录音/转写/账户）。
- [ ] 默认不使用原始录音训练；如需须单独可撤回授权。
- [ ] 事件带四元组幂等键；客户端草稿补传；任何异常不静默丢答案。
- [ ] 传输 TLS、敏感字段加密、后台最小权限与审计。
