# 产品方案：从「训练」到「做题」——细分领域题库

- 日期：2026-10-23
- 状态：Phase 1 实施中（本会话）
- 关联任务卡：[2026-10-23-practice-subtrack-mode.md](../tasks/2026-10-23-practice-subtrack-mode.md)

---

## 1. 结论

题库不应只服务面试。把「专项训练」升级为「做题」：

> **方向 → 细分领域 → 初级/中级/高级 → 一组题（5/10）→ 先想后看解析 → 自评会/模糊/不会 → 掌握度与错题本**

它既是日常学习入口，也是面试前的针对性补强。当前内容库 600 题、20 个细分领域、每难度 200 题，足够支撑第一版。

---

## 2. 可参考的优秀案例

| 产品             | 可借鉴点                                         | 落到 MentorLoop                              |
| ---------------- | ------------------------------------------------ | -------------------------------------------- |
| LeetCode         | 题库按 topic + difficulty 筛选，题单与进度可视化 | 方向/细分领域/难度筛选 + 已做/掌握度统计     |
| 牛客面试题库     | 按岗位、公司、题型组织，题目 + 参考答案 + 讨论   | 按细分领域组织，题目 + 参考解析 + 知识点标签 |
| Anki             | 自评「again / hard / good」驱动复习节奏          | 自评「不会 / 模糊 / 会」，不会进错题本       |
| Duolingo         | 技能路径与掌握度，短会话低门槛                   | 每次 5/10 题的小组练习 + 细分领域掌握度      |
| 极客时间每日一题 | 固定节奏的轻量入口                               | 「今日一题」与连续做题天数（Phase 2）        |

**取舍**：不做选择题（题库是开放题，改造成本高且失真）；用「先想后看解析 + 自评」保留开放题的训练价值，同时获得可追踪的掌握度。

## 3. 信息架构

```
成长
└─ 做题（原专项训练）
   ├─ 方向：前端 / 后端 / 运维 / AI 工程

   └─ 错题本（本地）→ 复习房间
```

首页「今日闭环」第三步与报告页的「做题」入口统一指向此处。

## 4. 细分领域（20 个）

| 方向    | 细分领域                                                                     | 内容重心                                    |
| ------- | ---------------------------------------------------------------------------- | ------------------------------------------- |
| 前端    | 浏览器与 Web 基础 / 前端应用与框架 / 小程序 / 桌面端 / 前端架构              | 渲染、JS/CSS、React/Vue、跨端、工程化       |
| 后端    | 微服务与分布式 / 数据与实时计算 / 数据库与缓存 / Web 后端 / 游戏后端         | 拆分与一致性、数仓/Spark/Flink、MySQL/Redis |
| 运维    | Kubernetes / SRE 与稳定性 / DevOps 与 CI/CD / 云平台与治理 / 安全 / 传统运维 | 调度网络存储、监控容量、流水线、云产品      |
| AI 工程 | 算法与模型 / 应用与大模型 / 推理与基础设施 / MLOps 与评估                    | 训练微调、RAG/Agent、推理压缩、评测         |

命名与 id 以 `data/subtracks.uts` 为单一来源；服务端按 `questions.subtrack` 过滤。

## 5. 做题房间交互

1. 题目卡：题号 / 细分领域 / 难度 / 知识点。
2. 先想：默认只显示题面与提示「先在心里作答，再查看解析」。
3. 查看解析：展示 `expectedEvidence`（参考解析 · 节选，400 字），标注知识点与技术栈。
4. 自评：不会 / 模糊 / 会 → 记录掌握度；「不会」进入错题本。
5. 下一题；最后一题后进入小组小结：会/模糊/不会数量、错题列表、再来一组/返回。
6. 错题复习：从本地错题本直接出题；复习时选「会」自动移出错题本。

**文案纪律**：不承诺结果、不出现实时分数；解析标注「参考解析 · 节选」，不伪装成完整标准答案。

## 6. 数据与实现

- API：复用 `POST /training/questions`，新增可选 `subtrack` / `difficulty`（见契约冻结）。
- 精确难度：传 `difficulty` 时候选池按难度精确过滤，不受经验档位白名单影响。
- 本地进度：`store/practice-progress.uts`，记录最近做题、各领域掌握度、错题（最多 100 题）。
- 解析：本期用既有 `expectedEvidence`（答案前 400 字）；Phase 2 增加 `reference_answer` 列存全文，并做旧数据回填。
- 不做服务端排程；Phase 2 引入 SRS（不会 1 天、模糊 3 天、会 7 天）。

## 7. 路线图

| 阶段            | 内容                                                              |
| --------------- | ----------------------------------------------------------------- |
| Phase 1（本期） | 细分领域 × 难度选题、做题房间、自评、错题本、本地掌握度、文案改口 |
| Phase 2         | 完整解析全文入库、SRS 复习队列、今日一题/连续天数、跨设备同步     |
| Phase 3         | 公司/岗位题单、错题导出、按报告优先改进项自动组题                 |

## 8. 成功指标

- 做题周活 / 人均每周题数
- 细分领域覆盖率（有多少领域被做过）
- 错题复习转化率（错题再次做对的占比）
- 做题 → 面试转化率（做完题后 7 天内开一场面试）
