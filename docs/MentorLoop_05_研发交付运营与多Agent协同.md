# MentorLoop AI 面试产品：研发交付、运营与多 Agent 协同

## 1. 推荐团队配置

| 角色         | 核心职责                                         |
| ------------ | ------------------------------------------------ |
| 产品负责人   | 用户研究、范围控制、PRD、定价与指标              |
| UI/UX 设计师 | 设计系统、面试房间、报告阅读体验、可用性测试     |
| 客户端工程师 | uni-app x、UTS、性能、音频与多端发布             |
| 后端工程师   | 账户、题库、会话、报告、支付、后台与数据         |
| AI 工程师    | 题目图谱、面试编排、追问、评分、评测与模型网关   |
| QA/DevOps    | 自动化测试、真机测试、发布、监控、安全与故障演练 |
| 内容运营     | 题目审核、岗位资料、报告文案、用户反馈与客服     |

小团队可由 4–5 名核心成员兼任，但不应省略 QA、题库审核或 AI 评测责任。

## 2. 里程碑

### M0：立项与技术预研（第 1–2 周）

- 冻结首发岗位、用户范围和合规边界。
- 完成 uni-app x 音频、数字人、弱网 POC。
- 定义题目数据结构、评分量表、会话协议和埋点字典。

### M1：可用原型（第 3–8 周）

- 小程序完成简历输入、岗位选择、标准面试、基础报告。
- 一个数字人角色、一个岗位题目图谱、人工审阅报告流程。
- 小范围内测，观察完成率、追问体验和报告价值。

### M2：商业 MVP（第 9–18 周）

- 完成题库后台、AI 简历优化、专项训练、支付、会员、运营埋点。
- App Beta、断点恢复、监控、告警、性能和隐私验收。
- 建立模型评测集与人工抽检制度。

### M3：上线与增长（第 19 周起）

- 小程序正式发布，App 分批发布。
- 持续优化漏斗、价格、报告、训练计划和题目质量。
- 依据用户数据决定扩展岗位或推进机构版。

## 3. 多 Agent 协同方案

多 Agent 用于内部交付，不进入最终用户产品。建议创建一个项目协作 Skill，要求每项任务均包含：目标、范围、依赖、验收标准、风险、产物路径和负责人。

| Agent         | 固定产物                                     |
| ------------- | -------------------------------------------- |
| 产品 Agent    | PRD、用户旅程、需求优先级、埋点与验收用例    |
| AI Agent      | 能力图谱、题目卡、追问规则、评分量表、评测集 |
| 设计 Agent    | 页面流、组件规范、交互状态、可访问性说明     |
| 客户端 Agent  | 页面、UTS 插件接口、性能基线、真机兼容报告   |
| 后端 Agent    | OpenAPI、数据模型、任务编排、权限与监控      |
| QA/安全 Agent | 测试计划、漏洞清单、回归报告、发布准入结论   |
| 运营 Agent    | 题库审核规则、上新计划、客服 FAQ、增长复盘   |

协同原则：

1. AI Agent 不能单独决定产品规则，必须由产品和内容审核确认。
2. 客户端与后端先冻结接口契约，再并行开发。
3. 每次模型或评分规则变更都必须运行固定评测集。
4. 发布必须由 QA/安全 Agent 给出准入结论，不能以“功能能跑”替代质量验收。

## 4. 运营机制

- 内容：每周更新题目并进行难度、质量和重复率审查。
- 质量：抽样复核 AI 报告的事实性、可解释性、公平性和不当建议。
- 增长：监测“完成面试 → 查看报告 → 开始训练 → 再次面试 → 付费”的漏斗。
- 客服：建立录音、报告、支付、隐私删除和模型反馈的标准响应流程。
- 风险：对误导性职业建议、歧视性表达、用户隐私和声纹数据设立专项处置机制。
