**核实到的版本事实（2026-09-20）**：

- Vue **3.5.43（npm latest）** —— ⚠️ 后经 `pnpm install` 实测更正：Vue 3.6 **尚未 GA**，npm 上只有 alpha/beta/rc；原记的"3.6 已正式发布"是错的。uni-app x 的 Vue（含蒸汽模式）由 DCloud 编译器内置，与 npm `vue` 版本解耦。
- Vite **8** 已落地，engines 要求 `^20.19.0 || >=22.12.0`。
- Tailwind CSS **4.3.x**：CSS-first 配置（`@import "tailwindcss"` + `@theme`），不再默认生成 tailwind.config.js；`@tailwindcss/vite` peer 支持 vite ^5.2/^6/^7/^8。
- Node **24 LTS**（Active LTS 至 2028-04-30）；pnpm **11.x** 为 latest 稳定（12.x 是 Rust 重写、opt-in）。

**两条关键结论（重要，避免以后重复踩坑）**：

1. **更正**：uni-app x **支持** Tailwind —— `weapp-tailwindcss` v5 的 `uniAppX()` preset 已支持 uni-app x + Tailwind 4（微信/安卓/iOS/鸿蒙已验证）。我此前判断"不支持"是错的。限制：原生端不支持 `gap`/`gap-x`/`gap-y`/`space-x`/`space-y`，需改用 `mt-*`/`ml-*`；不要同时注册 `@tailwindcss/vite`；需 HBuilderX ≥ 5.11、Node ≥ 22.18/24.11。
2. **Vapor 在小程序与原生 App 上不可行**：Vapor 编译产物是直接 DOM 操作，小程序（WXML+setData）与 uni-app x 原生视图**没有 DOM**。Vapor 只能用于 Web/H5/SSR。这是硬约束。

**因此推荐架构**：pnpm workspace monorepo —— `apps/web`（Vue 3.6 + Vapor + Vite 8 + Tailwind 4）承载 Vapor；`apps/mobile`（uni-app x + weapp-tailwindcss）承载小程序/App；`packages/shared` 复用领域模型与 API 契约；`packages/theme` 统一设计 token。

### 重要更正（用户质疑后查官方文档验证，务必记住）

用户质疑"Vapor 不支持"的结论、要求查官方文档。**结果证明我错了**：

**uni-app x 支持 Vapor（官方叫「蒸汽模式」，即 vapor）**。官方文档 https://uniapp.dcloud.net.cn/uni-app-x/app-vapor.html 原文：

- "蒸汽模式，即 vapor，是 vue3 的新功能，去掉了虚拟 DOM。"
- "uni-app x 的蒸汽模式，包含了去掉虚拟 DOM 的 vue 框架，以及 App 平台的一套基于**原生渲染管线**的、超过原生渲染速度的全新渲染引擎。"

→ DCloud 没靠 DOM 实现，而是为 App 自建原生渲染管线，所以我"无 DOM 故不支持"的推断不成立。

**蒸汽模式官方支持矩阵**：鸿蒙 HBuilderX 5.0+ / iOS 5.11+ / Android 5.21+；**小程序与 Web 当前降级为 VDOM 模式运行**（官方称后续升级）。
启用：manifest.json → `uni-app-x.vapor: true`；`vapor-render-target: 'bytecode'|'nativecode'`（默认 bytecode）；条件编译 `// #ifdef VUE3-VAPOR`。

**蒸汽模式硬约束（影响现有代码）**：

1. **仅支持组合式 API（`<script setup>`），不支持选项式 API、不支持 mixin** → 现有 37 个文件全是选项式，若开蒸汽模式必须全量改造为组合式。
2. CSS 避免复杂关系选择器（`.a .b`）→ 与 Tailwind 原子类天然契合。
3. 性能测试须用 release/正式包，勿用 debug。

**架构结论修正**：不再需要为 Vapor 单独建 Web 子项目，现有 uni-app x 单仓开启蒸汽模式即可。

**方法论教训（重要）**：涉及框架能力"支持/不支持"的判断，**必须先查官方文档**，不能只靠原理推断或第三方博客。本次两处结论都因未查官方文档而出错（第一次误判 Tailwind 不支持，第二次误判 Vapor 不支持）。

## W1–W8 实施（用户指令「开始」后执行）

按定稿方案落地，同时发现并修正了上一轮建骨架时的 **3 处结构性错误**：

**修正 1：文件后缀** —— uni-app x 官方模板是 `App.uvue` / `main.uts` / `pages/**/*.uvue`，我上一轮建的 `.vue` 后缀不符合规范。已全部重建为 `.uvue`（15 个：App + 5 组件 + 9 页面）并新增 `main.uts`。

**修正 2：UTS 不支持 interface** —— 官方 `uts_diff_ts` 文档：对象字面量仅支持构造 `type` 定义的对象类型，**不支持 interface**；不支持 `undefined`（用 null）；不支持匿名对象字面量作参数/返回类型。已把 types/store/api 全部 `interface` → `type`，新增 `SessionRef` / `AnswerAck` / `RequestOptions` / `ApiResult` 等命名类型，对象字面量统一加 `as NamedType`。

**修正 3：Vue 3.6 未 GA** —— 见上。

**已落地内容**：

- 基座：`.nvmrc` `.gitignore` `.editorconfig` `.npmrc` `package.json`（pnpm 11 / Node 24）`tsconfig.json` `env.d.ts` `index.html` `main.uts` `App.uvue`。
- 蒸汽模式：`manifest.json` → `uni-app-x.vapor: true` + `vapor-render-target: bytecode`；`pages.json` globalStyle 加 `styleIsolation: "2"`。
- Tailwind 4：`main.css`（`@import 'tailwindcss' source(none)` + `@source` App/pages/components + `@theme` 设计 token）；`vite.config.ts` 用 `WeappTailwindcss(uniAppX({ cssEntries: [main.css], cssOptions:{rem2rpx:true}, uvueUnsupported:'error' }))`。
- 全量组合式：15 个 `.uvue` 改为 `<script setup lang="uts">`（defineProps 运行时声明、defineEmits、ref/computed、onLoad/onUnload from `@dcloudio/uni-app`），样式全部改原子类；数字人去掉 `.s-listening .avatar-mouth` 后代选择器。
- 质量门禁：ESLint 9 flat config（.uvue 走 vue-eslint-parser + extraFileExtensions；.uts 用 no-restricted-syntax 禁用 interface）、Prettier（.uvue→vue parser）、husky + lint-staged + commitlint、Vitest（`vitest.config.ts` 内置 esbuild 插件把 `.uts` 按 TS 转译，从而脱离 HBuilderX 单测状态机）、`scripts/check-uvue-css.mjs`（拦截 gap/space-x-*）、GitHub Actions CI。
- 已本地验证：`node scripts/check-uvue-css.mjs` 通过（15 个 .uvue，退出码 0）。

**踩坑记录**：

- 不要用 `bg-white/5` 这类透明度修饰符 —— Tailwind 4 输出 `color-mix()`，原生端不支持，改内联 `rgba()`。
- `@dcloudio/vite-plugin-uni` 没有 4.x，dist-tags 是 `latest: 3.0.0-alpha-3000020210521001` / `vue3: 3.0.0-5020620260917001`；已按 vue3 tag 精确 pin。
- 原生端不支持 `gap`/`space-x-*`/`space-y-*`，统一用 `mt-*`/`ml-*`。
- uvue：`view` 默认 flex column，横向需写 `flex-row`；样式不继承，文字必须 `<text>` 且样式写在 `<text>` 上。
